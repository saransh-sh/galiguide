# SOLID Principles (Pragmatic Application)

Apply SOLID to real code, not as an excuse for premature layers.

- **Single Responsibility (S):** One reason to change per controller, function, component, or module.
- **Open/Closed (O):** Extend through function composition and pure functions rather than complex class hierarchies.
- **Liskov Substitution (L):** Test fakes and Neon PostgreSQL instances must honor identical Prisma contracts.
- **Interface Segregation (I):** Keep DTOs lean. Do not leak admin audit fields to public endpoints.
- **Dependency Inversion (D):** Decouple controllers from raw DB sockets via Prisma Client in `server/src/lib/prisma.ts`.
